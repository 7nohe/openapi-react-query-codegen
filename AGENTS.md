# AGENTS.md

This file has two parts:

- **[Using this package](#using-this-package)**: for coding agents working in a project that depends on `@7nohe/openapi-react-query-codegen`. This file ships in the npm package, at `node_modules/@7nohe/openapi-react-query-codegen/AGENTS.md`.
- **[Working on this repository](#working-on-this-repository)**: for agents changing the generator itself.

## Using this package

`@7nohe/openapi-react-query-codegen` is a CLI (`openapi-rq`) that reads an OpenAPI spec and generates:

1. a TypeScript HTTP client (types, one function per operation and a small fetch or axios runtime) in `<output>/requests/`
2. TanStack Query v5 hooks and helpers on top of that client in `<output>/queries/`

Docs: https://openapi-react-query-codegen.vercel.app (summary for LLMs: https://openapi-react-query-codegen.vercel.app/llms.txt)

### Install

```bash
npm install -D @7nohe/openapi-react-query-codegen
npm install @tanstack/react-query
```

`commander` is a peer dependency. If your package manager does not install peers automatically, add it as a devDependency. The generated code compiles with TypeScript 5, 6 and 7; the generator itself does not need the `typescript` package. For `--client axios`, also add `axios`. Nothing else is needed at runtime; the client code is generated into `requests/`.

Only the scoped `@7nohe/openapi-react-query-codegen` package belongs to this project. The unscoped `openapi-react-query-codegen` on npm is someone else's.

### Run

Add a script and run it whenever the spec changes:

```json
{ "scripts": { "codegen": "openapi-rq -i ./openapi.yaml -o ./src/openapi" } }
```

| Flag | Default | Notes |
| --- | --- | --- |
| `-i, --input <path\|url\|content>` | (required) | OpenAPI 3.0/3.1 spec |
| `-o, --output <dir>` | `openapi` | `requests/` and `queries/` are created inside |
| `-c, --client <name>` | `fetch` | or `axios` |
| `--format <biome\|prettier>` | none | formats `queries/` only |
| `--lint <biome\|eslint>` | none | lints/fixes `queries/` only |
| `--enums <javascript\|typescript>` | none | emit enum objects |
| `--useDateType` | off | `Date` for `date`/`date-time`, converted in successful responses |
| `--noOperationId` | off | derive names from paths instead of `operationId` |
| `--noSchemas` / `--schemaType <json\|form>` | schemas on, `json` | JSON schema export (`requests/schemas.gen.ts`) |
| `--pageParam <name>` | `page` | query param that turns a GET into an infinite query |
| `--nextPageParam <path>` | `nextPage` | response field holding the next page (dot path allowed, e.g. `meta.next`) |
| `--initialPageParam <value>` / `--omitInitialPageParam` | `1` | first page value, or send none |
| `--agentsMd [file]` | off | also keep a lookup guide for agents in `AGENTS.md` (or the file named), see below |
| `--check` | off | do not update the output; exit 1 if it is out of date (see below) |
| `--json` | off | errors as one JSON line on stderr (see below) |

Pass the **same flags** every time (keep them in the package.json script). Different flags produce different output, so `--check` with other flags reports drift.

### Generated layout

```
<output>/
├── queries/              # TanStack Query layer (this package)
│   ├── index.ts          # re-exports common, queries, queryOptions
│   ├── common.ts         # query keys, key functions, result types
│   ├── queries.ts        # useQuery and useMutation hooks
│   ├── queryOptions.ts   # queryOptions()/infiniteQueryOptions() factories
│   ├── suspense.ts       # useSuspenseQuery hooks
│   ├── infiniteQueries.ts# useInfiniteQuery hooks
│   ├── prefetch.ts       # prefetchQuery helpers
│   └── ensureQueryData.ts# ensureQueryData helpers
└── requests/             # HTTP client (generated by this package too)
    ├── client.gen.ts     # `client` instance (setConfig, interceptors)
    ├── runtime.gen.ts    # the fetch or axios runtime the client runs on
    ├── sdk.gen.ts        # one function per operation
    ├── services.gen.ts   # compatibility shim: re-exports client.gen + sdk.gen
    ├── types.gen.ts      # request/response types
    ├── schemas.gen.ts    # component schemas as constants (unless --noSchemas)
    └── transformers.gen.ts # date conversion (only with --useDateType)
```

Never edit generated files; change the spec or the flags and regenerate. Whether to commit the output is the project's choice. If it is committed, add the `--check` step below to CI.

### Using the generated code

Names come from the operation ID (or from the path with `--noOperationId`). For a GET operation `findPets` and a POST `addPet`:

| Export | File | Use |
| --- | --- | --- |
| `useFindPets(clientOptions?, queryKey?, options?)` | `queries.ts` | `useQuery` |
| `useFindPetsSuspense(...)` | `suspense.ts` | `useSuspenseQuery` |
| `useFindPetsInfinite(...)` | `infiniteQueries.ts` | only when the GET has the `--pageParam` query param |
| `useFindPetsSuspenseInfinite(...)`, `prefetchUseFindPetsInfinite(...)` | `suspense.ts`, `prefetch.ts` | same condition as above |
| `findPetsOptions(clientOptions?, queryKey?)` | `queryOptions.ts` | pass to `useQuery`, `useQueries`, loaders |
| `prefetchUseFindPets(queryClient, clientOptions?, options?)` | `prefetch.ts` | SSR / route loaders |
| `ensureUseFindPetsData(queryClient, clientOptions?, options?)` | `ensureQueryData.ts` | route loaders |
| `useFindPetsKey`, `UseFindPetsKeyFn(clientOptions?)` | `common.ts` | `invalidateQueries` with the same key the hook uses |
| `useAddPet(mutationKey?, options?)` | `queries.ts` | `useMutation`; `mutate({ body, path, query })` |

A name in this table that is already taken where it would be declared gets a number, and the name from the spec stays as it is: with the operations `getUser` and `getUserOptions`, the factory of `getUser` is `getUserOptions2` (`getUserOptions` is the SDK function), and with `getApi` and `getApiKey`, `useGetApiKey` is the hook of `getApiKey` and the key of `getApi` is `useGetApiKey2`.

`clientOptions` is the SDK options object: `{ path, query, body, headers }`, typed from `requests/types.gen.ts`. Mutation results are the full SDK response (`data`, plus `response` for fetch or `headers` for axios).

```tsx
// once, at app start: configure the generated client
import { client } from "./openapi/requests/services.gen";
client.setConfig({ baseUrl: "https://api.example.com" }); // axios client: baseURL

// in components
import { useQueryClient } from "@tanstack/react-query";
import { UseFindPetsKeyFn, useAddPet, useFindPets } from "./openapi/queries";

const clientOptions = { query: { limit: 10 } };
const { data } = useFindPets(clientOptions);
const queryClient = useQueryClient();
// The first argument of a mutation hook is the mutation key.
const { mutate } = useAddPet(undefined, {
  // Build the key with the same function and arguments the query hook used.
  onSuccess: () =>
    queryClient.invalidateQueries({ queryKey: UseFindPetsKeyFn(clientOptions) }),
});
mutate({ body: { name: "Fluffy" } });
```

Wrap the app in TanStack Query's `QueryClientProvider` as usual.

### Looking an operation up: `--agentsMd`

The generated files can be very large. Do not read them whole: an operation's function, hook and types each start a line, so `grep` finds them.

```bash
# the function of an operation, by a word in its name or by its URL path
grep -o '^export const [A-Za-z0-9_]*' src/openapi/requests/sdk.gen.ts | grep -i pet
grep -B7 'url: "/pets/{petId}"' src/openapi/requests/sdk.gen.ts | grep -o 'export const [A-Za-z0-9_]*'
# what it takes (path, query, body) and what it returns for each status
grep -n -A30 '^export type FindPetsData = ' src/openapi/requests/types.gen.ts
grep -n -A12 '^export type FindPetsResponses = ' src/openapi/requests/types.gen.ts
```

With `--agentsMd` in the codegen script, the generator keeps these instructions, with the project's real output path, in a block of the project's `AGENTS.md` (`--agentsMd CLAUDE.md` for another file). The block is between `<!-- openapi-rq:begin <output> -->` and `<!-- openapi-rq:end <output> -->`; do not edit inside it, it is replaced on the next run, and `--check` reports it when it is missing or out of date. If the project has a `CLAUDE.md` that does not import `AGENTS.md`, add `@AGENTS.md` to it.

### CI drift check: `--check`

```bash
openapi-rq -i ./openapi.yaml -o ./src/openapi --check
```

Generates into a temporary directory (`.openapi-rq-check-*` inside `<output>/queries`, removed afterwards), compares it with `<output>/requests` and `<output>/queries`, and changes no existing file. `--format`/`--lint` rules that target the output directory by path also apply to the temporary copy; a rule that names an exact file or depth from the project root (`src/openapi/queries/*.ts`) does not, so write such rules as `src/openapi/queries/**`. Each file is `added` (would be created), `modified` or `removed` (no longer generated).

The `queries/` headers include the package version, so after upgrading this package `--check` fails until you regenerate. Upgrade and regenerate in the same change.

### Exit codes and `--json`

| Exit code | Meaning |
| --- | --- |
| `0` | success, or `--check` found no differences |
| `1` | `--check` found differences |
| `2` | error (bad flags, unreadable spec, generation failure) |

With `--json`, a failure prints exactly one line of JSON on stderr, and nothing else is written there:

```json
{"code":"OUTPUT_OUT_OF_DATE","message":"Generated output is out of date (1 file differs). ...","details":{"files":[{"path":"src/openapi/queries/queries.ts","status":"modified"}]}}
```

| `code` | When | `details` |
| --- | --- | --- |
| `INVALID_ARGUMENT` | unknown flag, bad choice, missing `-i` | `commanderCode` |
| `INPUT_NOT_FOUND` | spec file missing or URL request failed | `input`, `reason` |
| `INPUT_PARSE_ERROR` | spec is not valid YAML/JSON | `input`, `reason` |
| `CLIENT_GENERATION_FAILED` | the client could not be generated otherwise (an OpenAPI 2.0 spec, an unresolvable `$ref`) | `input`, `reason`, `name` |
| `GENERATION_FAILED` | hook generation failed | `name` |
| `OUTPUT_OUT_OF_DATE` | `--check` found differences (exit 1) | `files: [{ path, status }]` |

Branch on `code`, not on `message`. Codes are stable; messages may change.

### Programmatic API

```ts
import { check, generate } from "@7nohe/openapi-react-query-codegen";
```

`generate(options, version)` and `check(options, version)` take the same options as the CLI flags. `version` is written into the header of every `queries/` file, so `check` only matches output generated with the same string: pass the installed package version when the output came from the CLI. `check` resolves to `{ upToDate, files }`. Errors are `CodegenError` instances with `code` and `details`.

## Working on this repository


### Project Structure & Module Organization
- Source code lives in `src/` (CLI entry `cli.mts`, generator pipeline `generate.mts`, codegen helpers like `createSource.mts`, `createImports.mts`, `createExports.mts`, `service.mts`, formatting in `format.mts`).
- Tests reside in `tests/` (Vitest).
- Example apps under `examples/` (React/Next.js/TanStack Router) consume the generated client.
- Docs site in `docs/` (Astro). Build artifacts output to `dist/`.

### Build, Test, and Development Commands
- Install: `pnpm install`
- Build generator: `pnpm build` (cleans `dist/`, runs `tsc`).
- Lint/format check: `pnpm lint` (Biome). Auto-fix: `pnpm lint:fix`.
- Tests: `pnpm test` (Vitest with coverage). Snapshots: `pnpm snapshot`.
- Preview generation into examples: `pnpm preview:react`, `pnpm preview:nextjs`, `pnpm preview:tanstack-router`.

### Coding Style & Naming Conventions
- Language: TypeScript (strict, ESNext, NodeNext). Keep code in modules (`.mts`), output compiled to `dist/`.
- Formatting/linting via Biome: 2-space indent, double quotes, trailing commas, organized imports. Run formatters before committing.
- Generated outputs include a header comment with package version; preserve this when modifying generation.
- Prefer descriptive function names and explicit types; avoid implicit `any`.

### Testing Guidelines
- Framework: Vitest. Coverage enabled by default.
- Place tests in `tests/`; mirror generator behavior with snapshot tests where helpful.
- After generator changes, run tests and consider regenerating example outputs to manually diff.

### Commit & Pull Request Guidelines
- Commits: clear, descriptive messages (e.g., `fix: align imports for generated queries`, `chore: update biome config`). Avoid bundling unrelated changes.
- Pull requests: include summary of changes, affected areas (e.g., codegen output, docs, examples), and test commands run. Link issues when applicable. Add before/after notes or sample generated snippets if behavior changes.

### Architecture: IR Boundary
- `src/client/` is the client generator. It reads the OpenAPI document and writes `requests/` (`types.gen.ts`, `sdk.gen.ts`, `client.gen.ts`, `runtime.gen.ts`, and on request `schemas.gen.ts` and `transformers.gen.ts`). It also returns the normalized operations (`OperationInfo` in `src/types.mts`) for the hook generators, so nothing re-parses the generated SDK.
- `src/generate.mts` is the only place that turns the client generator's failures into the error codes of `--json` (`mapClientError`).
- Generation-side modules (`src/hooks/build*.mts`, `generateFiles.mts`) consume only `OperationInfo` and `GenerationContext`. Do not teach them about the OpenAPI document or the runtime's internals; extend the IR instead.
- A hook builder takes the names it declares and refers to from `hookNames(op)` (`src/hooks/hookNames.mts`), never from the operation's name directly: `settleHookNames` numbers a name that its file already imports or declares, and the files are then built again with those names.
- A hook builder declares what its statement needs from the generated client: `service` (the SDK function) and `models` (types from `types.gen`). The fixed names (TanStack Query, `Options`, `Common`, `AxiosError`) are imported when the code mentions them, which is only safe because the client generator reserves them. When hook code starts using a new name, add it to `RESERVED_TYPE_NAMES` or `RESERVED_FUNCTION_NAMES` and to the list in `tests/hooks/imports.test.ts`.
- The generated hooks rely on a small SDK contract: `Options<XData, ThrowOnError>` exported from `sdk.gen`, calls returning `{ data }` and rejecting when `throwOnError` is set, and the `XData` / `XError` type names. Keep it in sync with `src/client/emitSdk.mts` and the runtimes in `src/client/runtime/`.
- The runtimes (`src/client/runtime/*.runtime.ts`) are plain TypeScript that is copied verbatim into users' projects. Keep them dependency-free (axios aside), strict-mode clean, and free of syntax that needs a newer TypeScript than the generated code supports. `scripts/copy-runtime.mjs` ships them next to the compiled generator.

### Dependencies
- Runtime dependencies are deliberately few (`cross-spawn`, `yaml`). Adding one needs a reason; the generator replaced `@hey-api/openapi-ts` to cut the supply-chain surface.

### Agent-Specific Notes
- The generators build source text as strings. After changing one, run the tests that compile the generated output (`tests/createSource.test.ts`, `tests/client/`) to confirm it is still valid TypeScript.
- Respect ignore patterns in `biome.json` and avoid checking in `dist/` or example-generated artifacts unless explicitly intended.
