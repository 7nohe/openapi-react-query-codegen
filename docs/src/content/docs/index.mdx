## From a specification to a typed call

<Steps>

1. Install the generator next to TanStack Query.

   ```bash
   npm install -D @7nohe/openapi-react-query-codegen
   npm install @tanstack/react-query
   ```

2. Generate. Run it again whenever the specification changes.

   ```bash
   npx openapi-rq -i ./petstore.yaml -o ./src/openapi
   ```

3. Call an operation. Its parameters, its response and its errors are typed from the specification.

   ```tsx
   import { useFindPets } from "./openapi/queries";

   function Pets() {
     const { data } = useFindPets({ query: { limit: 10 } });
     return <ul>{data?.map((pet) => <li key={pet.id}>{pet.name}</li>)}</ul>;
   }
   ```

</Steps>

## What lands in your project

<FileTree>

- src/openapi
  - queries
    - index.ts re-exports the three files below
    - queries.ts `useQuery` and `useMutation` hooks
    - queryOptions.ts `queryOptions()` factories for loaders and `useQueries`
    - common.ts query keys and key functions for invalidation
    - suspense.ts
    - infiniteQueries.ts
    - prefetch.ts
    - ensureQueryData.ts
  - requests
    - sdk.gen.ts one function per operation
    - types.gen.ts request and response types
    - client.gen.ts the client to configure (base URL, interceptors)
    - runtime.gen.ts the fetch or axios runtime, no package to install
    - schemas.gen.ts

</FileTree>

The client is plain TypeScript in your repository: there is no runtime package to keep in step with the generator, and the code works without React too.

## Made for CI and for coding agents

- `--check` regenerates into a temporary directory and fails when the committed output is out of date. [Add it to CI](/guides/ci-and-agents/).
- `--json` prints errors as one line of JSON with a stable code.
- `--agentsMd` keeps a short guide in your `AGENTS.md` that tells a coding agent how to look one operation up instead of reading the generated files. In our runs it cut what the agent had to read by a quarter to a third. [See the measurements](/guides/benchmarks/#coding-agents).
