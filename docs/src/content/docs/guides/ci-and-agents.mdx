## Checking for drift in CI: `--check`

If you commit the generated `openapi/` directory, run the generator with `--check` in CI so a spec change can't be merged without regenerating:

```bash
openapi-rq -i ./openapi.yaml -o ./src/openapi --check
```

Use exactly the same options as your normal codegen script. Different options produce different output, and `--check` reports that as drift. A simple way is to reuse the script:

```json
{
  "scripts": {
    "codegen": "openapi-rq -i ./openapi.yaml -o ./src/openapi --format biome",
    "codegen:check": "npm run codegen -- --check"
  }
}
```

`--check`:

- generates into a temporary directory next to the output directory (`.openapi-rq-check-*`), so `--format` and `--lint` pick up the same configuration files and ignore rules as a normal run, and deletes it afterwards
- compares only the directories the generator owns: `<output>/requests` and `<output>/queries`
- never writes to the output directory
- exits with `0` when everything matches, and with `1` when files differ

```
error [OUTPUT_OUT_OF_DATE]: Generated output is out of date (2 files differ). Re-run openapi-rq without --check to update it.
  modified src/openapi/queries/queries.ts
  added    src/openapi/requests/sdk.gen.ts
```

| Status | Meaning |
| --- | --- |
| `added` | Generation produces this file, but it is missing from the output |
| `modified` | The file content differs |
| `removed` | The file exists in the output but is no longer generated |

A GitHub Actions step looks like this:

```yaml
- run: npm ci
- run: npm run codegen:check
```

## Machine-readable errors: `--json`

With `--json`, a failure prints exactly one line of JSON to stderr. The logs of `@hey-api/openapi-ts` are silenced, so stderr contains nothing else.

```json
{"code":"INPUT_NOT_FOUND","message":"OpenAPI input could not be read (file not found or request failed): ./openapi.yaml","details":{"input":"./openapi.yaml"}}
```

The shape is always `{ code, message, details }`. `code` is stable and meant for branching; `message` is for humans and may change. `details` is an object whose fields depend on the code:

| `code` | When | `details` |
| --- | --- | --- |
| `INVALID_ARGUMENT` | Unknown option, invalid choice, missing `-i` | `commanderCode` |
| `INPUT_NOT_FOUND` | The input file does not exist or the URL request failed | `input` |
| `INPUT_PARSE_ERROR` | The input is not valid YAML or JSON | `input`, `reason` |
| `CLIENT_GENERATION_FAILED` | `@hey-api/openapi-ts` failed for another reason | `input`, `reason`, `name` |
| `GENERATION_FAILED` | Generating the React Query hooks failed | `name` |
| `OUTPUT_OUT_OF_DATE` | `--check` found differences | `files: [{ path, status }]` |

`--json` combines with `--check`. Drift is then reported as `OUTPUT_OUT_OF_DATE` with the list of files.

## Exit codes

| Exit code | Meaning |
| --- | --- |
| `0` | Success, or `--check` found no differences |
| `1` | `--check` found differences |
| `2` | Error |

Exit codes are the same with and without `--json`.

## Programmatic API

Both features are also available from Node.js:

```ts
import { check, CodegenError, generate } from "@7nohe/openapi-react-query-codegen";

const result = await check(
  {
    input: "./openapi.yaml",
    output: "./src/openapi",
    pageParam: "page",
    nextPageParam: "nextPage",
    initialPageParam: 1,
  },
  "local",
);
if (!result.upToDate) {
  console.log(result.files); // [{ path, status }]
}
```

Failures are thrown as `CodegenError`, which has the same `code` and `details` as the JSON output.

## Coding agents: AGENTS.md and llms.txt

- The npm package ships an [`AGENTS.md`](https://github.com/7nohe/openapi-react-query-codegen/blob/main/AGENTS.md). After installing, it is at `node_modules/@7nohe/openapi-react-query-codegen/AGENTS.md`. It covers installation, every CLI flag, the generated file layout, naming conventions for the generated hooks, and the error codes above. You can point your project's own `AGENTS.md` or `CLAUDE.md` at it.
- This site serves an [`llms.txt`](/llms.txt) with a short project summary and links to these docs.
