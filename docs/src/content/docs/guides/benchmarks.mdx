## Coding agents

The generated files are large: for the GitHub API, `queries.ts` alone is 1.5 MB. We gave Claude Code five small tasks in a project with that client ("write a component that lists a repository's open issues", and the like), ten runs per model and setup, and counted what it took.

A run passes when the component exists, uses the right hook and the project type-checks. The numbers are medians.

- **An agent does not read the files whole.** It searches them, so every run passed, with or without help.
- **[`--agentsMd`](/guides/ci-and-agents/#coding-agents-a-guide-in-your-agentsmd) saves the searching around.** With the lookup instructions in the project's `AGENTS.md`, the agent goes straight to the operation it needs.
- **Where the instructions are matters more than what they offer.** The same guide inside the output directory changed nothing, because an agent that searches with `grep` never loads it. A lookup command, an index file and an MCP server did no better than the `grep` instructions, so the generator ships none of them.

The setups that were tried and every run are in [`benchmarks/agent`](https://github.com/7nohe/openapi-react-query-codegen/tree/main/benchmarks/agent).

## Reading the numbers

- The tools do not generate the same thing. This library and Kubb generate hooks, `@hey-api/openapi-ts` generates options factories, and `openapi-typescript` generates types.
- Times change from run to run by a few percent, and by more on a busy machine. Compare tools within one run.
- Ten agent runs per setup show a direction, not a precise saving.

## Running them yourself

```bash
node benchmarks/run.mjs \
  --work /tmp/orqc-bench \
  --spec petstore=./examples/petstore.yaml \
  --spec github=/path/to/github.json
```

[`benchmarks/README.md`](https://github.com/7nohe/openapi-react-query-codegen/blob/main/benchmarks/README.md) describes the options.
